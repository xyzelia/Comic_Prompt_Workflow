# Shot Extraction（文本 → 可画点 → Shot）

把一段文本变成「哪些地方该出图、每张图画什么」的流程。

产物 `beats.md` 是**给人看的文档**：编辑、作者、你自己都能读懂并直接批注，
不需要理解提示词技术。审过 `beats.md` 再进 storyboard，把人工闸放在最便宜的一步。

## 输出：`beats.md`

```markdown
---
title: "[Comic Title]"
source: story.md
beat_count: [N]
shot_count: [M]
---

# [Comic Title] — 分镜草稿

> [一句话故事] · 主要人物：[A、B] · 预计 [M] 张

阅读顺序即镜头顺序。每一条 Beat 是一个事件或一次情绪转折，
下面列出它由几颗镜头构成、每颗镜头画面里有什么。

---

## Beat 1 — [标题]

**原文**：story.md 第 1 段
**可画**：是
**画面**：夜晚的便利店门口，Lin 独自站着等雨停，手里拎着一把没打开的伞。
**转译**：原文写「她不想回家」，这里改成她迟迟不撑伞、盯着雨的动作。
**镜头**：
- 1-1 全景 · 雨中的便利店招牌与孤零零的 Lin
- 1-2 特写 · 手里的伞，雨水顺着伞尖滴

---

## Beat 2 — [标题]

**原文**：story.md 第 2 段
**可画**：部分
**画面**：猫窝空了。
**转译**：原文的「心里一沉」不直接画，用景别骤收：从猫窝特写切到 Lin 猛然站起。
**镜头**：
- 2-1 特写 · 空猫窝，垫子还留着压痕
- 2-2 中景 · Lin 站起，手停在半空

---

## Beat 3 — [标题]（不画）

**原文**：story.md 第 3 段
**处理**：纯背景交代，并入 Beat 4 的道具画面；不单独出图。
```

### 可读性要求

- `画面` 用完整句子写，不用 tag 罗列。让人读完就知道这张图长什么样。
- `转译` 只在原文无法直接画时出现，说清「原文这么写，图上这么表现」。
- `镜头` 每行格式固定：`编号 · 景别 · 内容`，方便扫读和批注。
- 不出现 Final Prompt 英文、提示词语法、模型参数。这是给人看的稿子。

## 流程

### ⓿ 分段读取（长文）

短篇几千字可以一次读完切完。更长的按场景分段读，但**结果写进同一份
`beats.md`**，不要产出多份文件。读完一段追加一段，最后统一编号。

### ① 切节拍

按「一个事件」或「一次情绪转折」切，**不按段落切**。
一段长描写可能只是一个节拍；三句话也可能含两个节拍。

自检：这个节拍能不能起个标题？起不出说明切错了。

### ② 判可画性

| 可画 | 不可画 |
|---|---|
| 具体动作、身体移动 | 纯心理描写 |
| 空间位置变化 | 抽象论说 / 解释 |
| 可见的冲突、对峙 | 概述式时间跳跃 |
| 道具被使用、交接 | 对话里交代的信息 |
| 表情与姿态转变 | 重复已知信息 |

判定为「部分」时，保留其中可画的瞬间，其余走 ③ 转译。
判定为「不画」的节拍标出来并说明去向（并入哪条 Beat / 转成什么道具），不要静默删除。

### ③ 转译（把画不出来的变成画得出来的）

| 原文形态 | 转译成 |
|---|---|
| 内心想法 | 肢体语言 / 表情 / 环境象征物 |
| 信息交代 | 可见道具（信、屏幕、照片） |
| 时间跳跃 | 前后环境对比，同机位不同状态 |
| 抽象关系 | 两人的距离、朝向、遮挡 |
| 情绪升级 | 景别收紧（远 → 中 → 近） |

**不要字面化比喻**：原文用「电锯切西瓜」形容某事，画的是那件事本身，不是电锯和西瓜。

### ④ 拆 Shot

- 一颗镜头 = 一个动作 + 一个时刻 + 一个机位。
- **一 Shot 一动词**：画面里同时发生的动作超过一个就拆开。拆不动说明该节拍要占 2-3 张。
- 一个 Shot 只保留当前时刻真正需要的人物；项目默认上限为 6 名具名角色，用户可按漫画类型或场景复杂度调小。多人使动作、归属或表情无法读清时应拆镜头，但不因超过两人就机械拆分。
- 单张镜头里只放一处关键信息（表情、道具、环境变化三选一）。

### ⑤ 密度

每千字约 2-4 张，按节拍密度浮动，不按字数硬算。
对话密集、心理描写多的段落出图少；动作、场景切换多的段落出图多。

### ⑥ 原文没写的事实，标 TODO

小说经常不交代外貌、房间陈设、时间地点细节。事实层一律写：

```markdown
**画面**：Lin 站在空猫窝前。房间陈设 TODO — 原文未交代。
```

此阶段不要把补充内容写成“原文事实”。TODO 用来保留来源边界，避免后续误以为某个颜色、材质或设计来自小说。

提示词阶段可以做另一件事：为了让画面完整，加入不带具体属性的通用元素，例如 `coat`、`chair` 或 `ceiling light`，让 NovelAI 自行决定外观。这样的生成补全不回写成原文设定，也不能改变剧情、人物身份或关键道具。

## 自检清单

写完 `beats.md` 后逐条过：

- [ ] 每条 Beat 都能起出标题
- [ ] 每条「不画」的 Beat 都写了去向
- [ ] 每条 Beat 至少一个可见动作或可见变化
- [ ] 每颗镜头只有一个动词
- [ ] 每颗镜头的画面用完整句子能读懂
- [ ] 没有把比喻字面化
- [ ] 原文未交代的事实都标了 TODO；没有把生成补全冒充原文设定
- [ ] 镜头总数在密度区间内

## 与其他阶段的关系

```
story.md → beats.md（本文件，人工审） → storyboard.md → prompts/（文本交付）
```

`beats.md` 只回答「画什么」，不回答「怎么生成」。
景别、角度、服装引用、英文提示词都在后一阶段完成。
