# 页面规划

`page-plan.md` 位于 Beat 与最终 Storyboard 之间，负责决定读者在哪一页获得哪些信息。先规划页面目的，再设计格子。

## 页面计划格式

```markdown
# Page Plan — [标题]

## Page 01 — [页面目的]

- Source Beats: Beat 1, Beat 2
- Opening State: [进入页面时人物／地点／道具状态]
- Core Change: [本页发生的主要变化]
- Ending State / Page Turn: [结束或翻页揭示]
- Suggested Panel Count: [N]
- Major Characters: [按身份去重]
- Local Appearances: [预计每格出场次数]
- Text Load: [none / light / medium / heavy]
- Detail Priority: [表情／动作／环境／文字等]
- Notes: [大格、静默格、反应格等]
```

## Panel 数决策

- 不预先为所有页面固定相同格数。
- 建立场景、普通对话和简单动作可使用较多小格，但仍需保证文字与人物可读。
- 重要表情、复杂互动、关键道具或细节越重要，越应减少 Panel 数并增加面积。
- 反应、停顿、揭示和页尾承接应得到独立阅读空间。
- 四格是可用结构，不是默认套版；采用时仍按项目 Reading Direction 明确顺序。
- 单格 Page 可以存在，但它是页面级记录；不写多格分格触发词。

## 人物预算

从 `project-settings.md` 读取：

- 每页不同主要人物上限，默认 6 名；
- 跨格角色 Prompt 方案；
- Visible text types；
- Reading direction；
- Default Page orientation；
- Additional layout restrictions；
- Prompt 的 Character 块数量不从局部出场次数推导；一个 Panel 可以使用基础画面块和多个详细主体块。

页面规划必须遵守附加 Layout 限制。该字段为 `none` 时没有额外项目级限制；否则逐项转成可检查条件，例如每页最多几格、是否固定 `2×2`、是否禁止斜格／破框／前景覆盖、末格是否全宽，以及全部页面是否必须共享同一网格。限制互相冲突或与剧情容量冲突时，不替用户选择，返回确认。

不同人物数量与局部出场次数分开计算。同一角色跨 3 格只算 1 名主要人物；最终可按每格基础画面、详细主体和其他局部信息组织任意数量的 Character 块。承担对白、关键动作或剧情作用的人物不能伪装成背景群众排除。

超过设置时：

1. 检查是否有不必要的重复出场；
2. 把多人事件拆成更清楚的焦点 Panel；
3. 仍过载时拆 Page；
4. 不静默漏掉角色或合并身份。

## 文字预算

- 画内文字必须有足够空间，不靠无限缩小字体解决。
- 长对白保留说话者、戏剧目的和关键内容；未经用户授权不改写原文。
- 原文过长且必须完整保留时，增加 Panel／Page 或把完整内容留在画外排版计划中，由用户确认。
- 先读位置的文字应放在阅读顺序较早的位置，避免尾巴交叉和遮挡关键表情／动作。

## 连续性

每页记录进入和结束状态：

- 人物位置、朝向和距离；
- Outfit 和临时服装状态；
- 持物、道具位置和损坏状态；
- 时间、光线和环境变化；
- 已经发生且后页必须延续的动作结果。

历史页码和文件名不能阻止必要的叙事重构。增删 Page 时备份并同步更新后续编号与引用。
